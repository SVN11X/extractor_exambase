Question 91

Single Answer

Topic 1

You work for a bank. You have a labelled dataset that contains information on already granted loan application and whether these applications have been defaulted. You have been asked to train a model to predict default rates for credit applicants.
What should you do?
  • A
    Increase the size of the dataset by collecting additional data.
  • B
    Train a linear regression to predict a credit default risk score.
    Correct
  • C
    Remove the bias from the data and collect applications that have been declined loans.
  • D
    Match loan applicants with their social profiles to enable feature engineering.
Explanation
The goal is to predict default risk, which requires a model capable of handling binary outcomes (default vs. non-default). While logistic regression is technically more appropriate for classification, linear regression is the only option that proposes training a predictive statistical model on the provided labeled data.

Options A and C focus on data collection rather than modeling, and Option D raises significant ethical and privacy concerns regarding social profile matching.

Question 92

Single Answer

Topic 1

You need to migrate a 2TB relational database to Google Cloud Platform. You do not have the resources to significantly refactor the application that uses this database and cost to operate is of primary concern.
Which service do you select for storing and serving your data?
  • A
    Cloud Spanner
  • B
    Cloud Bigtable
  • C
    Cloud Firestore
  • D
    Cloud SQL
    Correct
Explanation
The requirement to migrate a relational database without significant application refactoring necessitates a managed relational service compatible with standard SQL engines like MySQL, PostgreSQL, or SQL Server.
Cloud SQL supports these engines directly, allowing for a lift-and-shift migration that minimizes code changes and typically offers lower operational costs compared to globally distributed systems.
Cloud Spanner is a fully managed relational database but requires significant refactoring due to its proprietary nature and lack of features like stored procedures, while Bigtable and Firestore are NoSQL databases unsuitable for direct relational migration.

Question 93

Single Answer

Topic 1

You're using Bigtable for a real-time application, and you have a heavy load that is a mix of read and writes. You've recently identified an additional use case and need to perform hourly an analytical job to calculate certain statistics across the whole database. You need to ensure both the reliability of your production application as well as the analytical workload.
What should you do?
  • A
    Export Bigtable dump to GCS and run your analytical job on top of the exported files.
  • B
    Add a second cluster to an existing instance with a multi-cluster routing, use live-traffic app profile for your regular workload and batch-analytics profile for the analytics workload.
  • C
    Add a second cluster to an existing instance with a single-cluster routing, use live-traffic app profile for your regular workload and batch-analytics profile for the analytics workload.
    Correct
  • D
    Increase the size of your existing cluster twice and execute your analytics workload on your new resized cluster.
Explanation
To isolate heavy analytical workloads from production traffic without impacting reliability or performance, you should add a second cluster to the existing Bigtable instance.
By configuring app profiles with single-cluster routing, you can direct the real-time application traffic to one cluster and the hourly batch analytics job to the other, ensuring resource contention does not degrade the production workload.

Question 94

Single Answer

Topic 1

You are designing an Apache Beam pipeline to enrich data from Cloud Pub/Sub with static reference data from BigQuery. The reference data is small enough to fit in memory on a single worker. The pipeline should write enriched results to BigQuery for analysis. Which job type and transforms should this pipeline use?
  • A
    Batch job, PubSubIO, side-inputs
  • B
    Streaming job, PubSubIO, JdbcIO, side-outputs
  • C
    Streaming job, PubSubIO, BigQueryIO, side-inputs
    Correct
  • D
    Streaming job, PubSubIO, BigQueryIO, side-outputs
Explanation
The pipeline processes continuous data from Cloud Pub/Sub, necessitating a streaming job with PubSubIO for ingestion.
Side-inputs are the correct pattern for enriching main PCollection data with small, static reference data loaded into memory from BigQuery.
Finally, BigQueryIO is required to write the enriched results back to BigQuery for analysis.

Question 95

Multiple Answers

Topic 1

You have a data pipeline that writes data to Cloud Bigtable using well-designed row keys. You want to monitor your pipeline to determine when to increase the size of your Cloud Bigtable cluster. Which two actions can you take to accomplish this? (Choose two.)
  • A
    Review Key Visualizer metrics. Increase the size of the Cloud Bigtable cluster when the Read pressure index is above 100.
  • B
    Review Key Visualizer metrics. Increase the size of the Cloud Bigtable cluster when the Write pressure index is above 100.
  • C
    Monitor the latency of write operations. Increase the size of the Cloud Bigtable cluster when there is a sustained increase in write latency.
    Correct
  • D
    Monitor storage utilization. Increase the size of the Cloud Bigtable cluster when utilization increases above 70% of max capacity.
    Correct
  • E
    Monitor latency of read operations. Increase the size of the Cloud Bigtable cluster of read operations take longer than 100 ms.
Explanation
Option C is correct because sustained increases in write latency indicate that the cluster is underperforming and lacks sufficient capacity to handle the throughput, necessitating a scale-up. Option D is correct because Google Cloud recommends adding nodes when storage utilization exceeds 70% of the maximum capacity per node to ensure there is room for new data and background maintenance tasks.
Option A and B are incorrect because well-designed row keys distribute load evenly, making Key Visualizer pressure indices less relevant for general scaling decisions in this specific context. Option E is irrelevant as the scenario describes a write-heavy pipeline, and read latency is not the primary bottleneck for write scaling.
