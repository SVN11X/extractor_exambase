Question 336

Single Answer

Topic 1

You are designing a stateful data processing pipeline that reads data from a Cloud Storage bucket and writes transformed data to a BigQuery table. The pipeline must be highly available and resilient to zonal failures within the us-central1 region. You need to configure a Dataflow pipeline ensuring minimal disruption during a zonal outage. What should you do?
  • A
    Launch the Dataflow job with the --region=us-central1 parameter.
    Correct
  • B
    Deploy the Dataflow job to a single zone within us-central1 and configure it to use a regional persistent disk to store its state.
  • C
    Deploy the Dataflow job to a single zone within us-central1 and use a multi-regional Cloud Storage bucket to store its state.
  • D
    Launch the Dataflow job with the --zone=us-central1a parameter.
Explanation
Specifying the --region parameter (Option A) deploys the Dataflow job as a regional service, distributing workers across multiple availability zones within us-central1. This architecture ensures that if one zone fails, the remaining zones continue processing, providing high availability and resilience against zonal failures.
In contrast, deploying to a single zone (Options B, C, D) creates a single point of failure for the compute layer, meaning a zonal outage would disrupt the pipeline regardless of where state or storage is located.

Your team has created several BigQuery curated datasets containing anonymized industry benchmark data. You want to make these datasets easily discoverable and accessible for querying by external partner companies within their own Google Cloud projects. You need a secure and scalable solution. What should you do?
  • A
    Publish the datasets as listings within BigQuery sharing (Analytics Hub).
    Correct
  • B
    Export the datasets to partner-specific Cloud Storage buckets.
  • C
    Create authorized views for each dataset and grant access to each partner.
  • D
    Grant the roles/bigquery.dataViewer IAM role to the partner group email addresses on the datasets.
Explanation
Google Cloud Analytics Hub (BigQuery Sharing) is specifically designed to securely share curated data with external parties while maintaining control and auditability. It allows partners to access datasets via listings without requiring direct IAM grants or data duplication, satisfying the 'secure and scalable' requirement.

Question 338

Single Answer

Topic 1

Your organization stores highly personal data in BigQuery and needs to comply with strict data privacy regulations. You need to ensure that sensitive data values are rendered unreadable whenever an employee leaves the organization. What should you do?
  • A
    Use column-level access controls with policy tags and revoke viewer permissions when employees leave the organization.
  • B
    Use dynamic data masking and revoke viewer permissions when employees leave the organization.
  • C
    Use customer-managed encryption keys (CMEK) and delete keys when employees leave the organization.
  • D
    Use AEAD functions and delete keys when employees leave the organization.
    Correct
Explanation
Option D is correct because AEAD (Authenticated Encryption with Associated Data) functions in BigQuery allow for cell-level encryption tied to specific keys. When an employee leaves, deleting their associated key renders the encrypted data permanently unreadable, as decryption becomes mathematically impossible without the key. This differs from access controls or masking, which only hide data rather than making it cryptographically unrecoverable.

Question 339

Single Answer

Topic 1

You monitor and optimize the BigQuery instance for your team. You notice that a particular daily report that uses a large JOIN operation is consistently slow. You want to examine the query's execution plan to identify potential performance bottlenecks within the JOIN as quickly as possible. What should you do?
  • A
    Use the bg query --dry_run command to review the estimated number of bytes read and review query syntax.
  • B
    Run a query on the INFORMATION_SCHEMA.JOBS_BY_PROJECT view filtering by the job_ID and analyze total_bytes_processed.
  • C
    Review the BigQuery audit logs in Cloud Logging.
  • D
    Leverage BigQuery's Query History view and analyze the execution graph.
    Correct
Explanation
The BigQuery Query History view provides direct access to the execution plan and execution graph for previously run jobs.
Analyzing this visual graph allows you to identify specific bottlenecks, such as data skew or inefficient shuffle stages, within the JOIN operation.
This is more effective than dry runs (which only show syntax/bytes) or audit logs (which lack detailed execution metrics).

Question 340

Single Answer

Topic 1

Your company stores vital operational sales data in a BigQuery dataset in us-central1. Your company requires a disaster recovery plan to restore this data to us-east1 with a recovery point objective (RPO) of 24 hours and a recovery time objective (RTO) of 4 hours if us-central1 experiences an outage. You need to implement the disaster recovery plan while keeping costs and complexity to a minimum. What should you do?
  • A
    Set up continuous queries and Pub/Sub to stream data changes from BigQuery tables in us-central1 to us-east1.
  • B
    Manually export data to a CSV file in a multi-regional Cloud Storage bucket daily and use bq load to restore to us-east1.
  • C
    Configure BigQuery cross-region dataset replication from ns-central1 to us-east1.
    Correct
  • D
    Take daily BigQuery table snapshots in us-central1.
Explanation
BigQuery supports automatic cross-region dataset replication, which simplifies disaster recovery by maintaining a standby dataset in the target region (us-east1).
This feature meets the RPO and RTO requirements while minimizing operational complexity and cost compared to manual exports or custom streaming architectures.
