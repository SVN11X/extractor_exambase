You are working on a sensitive project involving private user data. You have set up a project on Google Cloud Platform to house your work internally. An external consultant is going to assist with coding a complex transformation in a Google Cloud Dataflow pipeline for your project. How should you maintain users' privacy?
  • A
    Grant the consultant the Viewer role on the project.
  • B
    Grant the consultant the Cloud Dataflow Developer role on the project.
  • C
    Create a service account and allow the consultant to log on with it.
  • D
    Create an anonymized sample of the data for the consultant to work with in a different project.
    Correct
Explanation
The primary goal is to maintain user privacy while allowing an external consultant to develop complex transformation logic.
Granting access to the production project, even with limited roles, risks exposure of sensitive data through logs or debugging.
Creating an anonymized sample in a separate isolated project ensures the consultant can validate their code without ever seeing private user data.

Question 27

Single Answer

Topic 1

You are building a model to predict whether or not it will rain on a given day. You have thousands of input features and want to see if you can improve training speed by removing some features while having a minimum effect on model accuracy. What can you do?
  • A
    Eliminate features that are highly correlated to the output labels.
  • B
    Combine highly co-dependent features into one representative feature.
    Correct
  • C
    Instead of feeding in each feature individually, average their values in batches of 3.
  • D
    Remove the features that have null values for more than 50% of the training records.
Explanation
Combining highly co-dependent (correlated) features reduces multicollinearity and dataset dimensionality, which accelerates training without significant loss of predictive information.
Removing features correlated with the output (A) would degrade accuracy, as these are valuable predictors.
Averaging arbitrary batches (C) destroys feature specificity, and dropping features with >50% nulls (D) discards potentially useful signals that could be imputed.

Question 29

Single Answer

Topic 1

Your company is streaming real-time sensor data from their factory floor into Bigtable and they have noticed extremely poor performance. How should the row key be redesigned to improve Bigtable performance on queries that populate real-time dashboards?
  • A
    Use a row key of the form .
  • B
    Use a row key of the form .
  • C
    Use a row key of the form #.
  • D
    Use a row key of the form >##.
    Correct
Explanation
Option D is correct because placing the sensor ID before the timestamp ensures that writes for different sensors are distributed across multiple tablets, preventing hotspotting. Starting a row key with a monotonically increasing timestamp (Options A and C) concentrates write traffic on a single node, degrading performance. Option B fails because it lacks a timestamp component, causing new readings to overwrite previous ones instead of appending them.

Question 30

Single Answer

Topic 1

Your company's customer and order databases are often under heavy load. This makes performing analytics against them difficult without harming operations.
The databases are in a MySQL cluster, with nightly backups taken using mysqldump. You want to perform analytics with minimal impact on operations. What should you do?
  • A
    Add a node to the MySQL cluster and build an OLAP cube there.
  • B
    Use an ETL tool to load the data from MySQL into Google BigQuery.
    Correct
  • C
    Connect an on-premises Apache Hadoop cluster to MySQL and perform ETL.
  • D
    Mount the backups to Google Cloud SQL, and then process the data using Google Cloud Dataproc.
Explanation
The goal is to perform analytics with minimal impact on the production OLTP database. Using an ETL tool to load data into Google BigQuery separates the analytical workload from the transactional system, preventing heavy analytic queries from degrading operational performance.

BigQuery is Google's managed serverless data warehouse, designed specifically for large-scale analytics, making it the optimal choice over on-premises solutions or processing tools like Dataproc that require additional compute infrastructure.
