Question 221

Single Answer

Topic 1

You store and analyze your relational data in BigQuery on Google Cloud with all data that resides in US regions. You also have a variety of object stores across Microsoft Azure and Amazon Web Services (AWS), also in US regions. You want to query all your data in BigQuery daily with as little movement of data as possible. What should you do?
  • A
    Use BigQuery Data Transfer Service to load files from Azure and AWS into BigQuery.
  • B
    Create a Dataflow pipeline to ingest files from Azure and AWS to BigQuery.
  • C
    Load files from AWS and Azure to Cloud Storage with Cloud Shell gsutil rsync arguments.
  • D
    Use the BigQuery Omni functionality and BigLake tables to query files in Azure and AWS.
    Correct
Explanation
The requirement is to minimize data movement while querying relational BigQuery data alongside external object stores in Azure and AWS. Options A, B, and C all involve physically copying or transferring data into Google Cloud, which violates the constraint of minimal movement. BigQuery Omni enables federated queries across clouds, allowing you to analyze data in Azure Blob Storage and Amazon S3 directly without ingestion, satisfying the goal.

Question 222

Single Answer

Topic 1

You have a variety of files in Cloud Storage that your data science team wants to use in their models. Currently, users do not have a method to explore, cleanse, and validate the data in Cloud Storage. You are looking for a low code solution that can be used by your data science team to quickly cleanse and explore data within Cloud Storage. What should you do?
  • A
    Provide the data science team access to Dataflow to create a pipeline to prepare and validate the raw data and load data into BigQuery for data exploration.
  • B
    Create an external table in BigQuery and use SQL to transform the data as necessary. Provide the data science team access to the external tables to explore the raw data.
  • C
    Load the data into BigQuery and use SQL to transform the data as necessary. Provide the data science team access to staging tables to explore the raw data.
  • D
    Provide the data science team access to Dataprep to prepare, validate, and explore the data within Cloud Storage.
    Correct
Explanation
Google Cloud Dataprep (Trifacta) is specifically designed as a serverless, low-code data preparation service that allows users to visually explore, cleanse, and validate data without writing code. It integrates directly with Cloud Storage, enabling the data science team to perform necessary data wrangling tasks using a graphical interface rather than manual SQL or pipeline coding.

Question 223

Single Answer

Topic 1

You are building an ELT solution in BigQuery by using Dataform. You need to perform uniqueness and null value checks on your final tables. What should you do to efficiently integrate these checks into your pipeline?
  • A
    Build BigQuery user-defined functions (UDFs).
  • B
    Create Dataplex data quality tasks.
  • C
    Build Dataform assertions into your code.
    Correct
  • D
    Write a Spark-based stored procedure.
Explanation
Dataform includes a native feature called assertions that allows you to define SQL-based tests for data quality within your transformation code.
These assertions are specifically designed to perform checks such as uniqueness and null value validation directly on tables or views.
Using assertions ensures efficient integration because they run automatically during the pipeline execution without requiring external tools or custom UDFs.

Question 224

Single Answer

Topic 1

A web server sends click events to a Pub/Sub topic as messages. The web server includes an eventTimestamp attribute in the messages, which is the time when the click occurred. You have a Dataflow streaming job that reads from this Pub/Sub topic through a subscription, applies some transformations, and writes the result to another Pub/Sub topic for use by the advertising department. The advertising department needs to receive each message within 30 seconds of the corresponding click occurrence, but they report receiving the messages late. Your Dataflow job's system lag is about 5 seconds, and the data freshness is about 40 seconds. Inspecting a few messages show no more than 1 second lag between their eventTimestamp and publishTime. What is the problem and what should you do?
  • A
    The advertising department is causing delays when consuming the messages. Work with the advertising department to fix this.
  • B
    Messages in your Dataflow job are taking more than 30 seconds to process. Optimize your job or increase the number of workers to fix this.
  • G
    Messages in your Dataflow job are processed in less than 30 seconds, but your job cannot keep up with the backlog in the Pub/Sub subscription. Optimize your job or increase the number of workers to fix this.
    Correct
  • D
    The web server is not pushing messages fast enough to Pub/Sub. Work with the web server team to fix this.
Explanation
Data freshness measures the delay between event time and processing completion, while system lag measures only the duration of active processing.
Since data freshness is high (40s) but system lag is low (5s), individual messages process quickly, indicating a large backlog exists in the subscription rather than slow per-message execution.
The job cannot ingest new messages as fast as they arrive, causing accumulated delay; thus, increasing throughput via optimization or scaling workers resolves the backlog.

Question 225

Single Answer

Topic 1

Your organization stores customer data in an on-premises Apache Hadoop cluster in Apache Parquet format. Data is processed on a daily basis by Apache Spark jobs that run on the cluster. You are migrating the Spark jobs and Parquet data to Google Cloud. BigQuery will be used on future transformation pipelines so you need to ensure that your data is available in BigQuery. You want to use managed services, while minimizing ETL data processing changes and overhead costs. What should you do?
  • A
    Migrate your data to Cloud Storage and migrate the metadata to Dataproc Metastore (DPMS). Refactor Spark pipelines to write and read data on Cloud Storage, and run them on Dataproc Serverless.
    Correct
  • B
    Migrate your data to Cloud Storage and register the bucket as a Dataplex asset. Refactor Spark pipelines to write and read data on Cloud Storage, and run them on Dataproc Serverless.
  • C
    Migrate your data to BigQuery. Refactor Spark pipelines to write and read data on BigQuery, and run them on Dataproc Serverless.
  • D
    Migrate your data to BigLake. Refactor Spark pipelines to write and read data on Cloud Storage, and run them on Dataproc on Compute Engine.
Explanation
Option A is correct because it leverages Dataproc Metastore (DPMS) to manage Hive-compatible metadata, ensuring minimal refactoring for existing Spark jobs while using Cloud Storage as the compatible Parquet storage layer.
This approach minimizes ETL overhead by keeping the file format and processing engine logic intact, rather than migrating data into BigQuery tables which would require schema conversion.
Although the prompt mentions making data available in BigQuery, this is achieved efficiently via BigQuery's ability to query external tables on Cloud Storage without moving or converting the underlying Parquet files.
